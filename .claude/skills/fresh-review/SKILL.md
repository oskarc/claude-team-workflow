# A fresh review before the owner

The owner's rule: a fresh reviewer each round, given only the result, the references and the checklist, never the
maker's conclusions; nothing reaches the owner until that review and the maker's own verdict agree. Numbers passing
is not the look: a result can pass every measure and still be wrong to the eye.

## The brief to the reviewer
- **What it judges:** the file paths of the result (pictures, the page, the text) and how to open them, at the size
  the user sees and close up.
- **What it judges against:** the reference pictures or documents (paths, what each shows), the checklist that applies
  (the area's standard, the task's done-when checks), the owner's own words on the thing (quoted from the rule file).
- **Not given:** the maker's report, its verdicts, its numbers, "this is fixed now". A tool's printed verdict on a sheet
  may stay; the reviewer is told it is a number, not the look.
- **The task:** item by item, keep / rework / reject, each with what it sees and where, and the three things that would
  most bother the owner. Plain words, under 400 words. No file edits.

For the readiness review's part f, the result is the feature's task list: the reviewer gets the use case, the end
sentence, the readiness file and the tasks, and answers "what would stop a user from reaching the end that is not on
this list?"

## After
- The maker writes its own verdict before reading the reviewer's, then compares.
- Where they disagree, the thing is looked at again (another view, a close-up) before deciding.
- Only an agreed "keep" goes to the owner, with the open points named. A "rework" goes back as one or two faults for
  the next round.
